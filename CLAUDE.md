# CLAUDE.md

KEYMASH_ is a live-coding toy: any text is a valid program (no syntax errors, ever). Four modes:
KEYMASH_ (lines → threads → visuals, music, speech), PETRI_ (lines → genomes → a cell culture),
COOKIE_ (the whole text → one recipe → cookies baked in 3D, eaten by tapping) and MYCELIUM_ (under construction:
the whole text → a photographic forest floor seen from the side).
README.md is the user-facing doc (running, architecture, conventions); each mode's language reference
lives in `src/modes/<id>/README.md`. Read them before larger changes.

## Commands

```sh
bun run dev          # Vite dev server; tsc + oxlint + oxfmt problems show in terminal and in-page overlay (starts closed: click its badge)
bun run build        # tsc + vite build -> dist/ (index.html, main chunk, one chunk per mode in BUILD_MODES of vite.config.ts — now keymash, petri; dev has every mode; served by GitHub Pages, needs http)
bun test             # test/vm.test.ts (fuzz: the VM must never throw), test/petri.test.ts, test/cookie.test.ts, test/mycelium.test.ts
bun run typecheck    # tsc (TypeScript 7, strict, noUnusedLocals, noImplicitOverride)
bun run lint         # oxlint (scripts/ is ignored)
bun run format       # oxfmt: printWidth 140, single quotes; *.md and public/ are not formatted
bun scripts/sheet.ts # re-render cheat-sheet pictures + the picture table in src/modes/<id>/README.md
bun scripts/icons.ts # re-render public/ icons from scripts/icon.svg
bun scripts/perf.ts  # MYCELIUM_ GPU perf report: frame time, cost per layer, overdraw, shader cost per fragment (--help)
```

The scripts use playwright-core (headless Chromium) under bun — no python. First run:
`bunx playwright-core install chromium-headless-shell`. tsc covers `scripts/` too; oxlint ignores it.

CI (`.github/workflows/check.yml`) runs lint, format:check, typecheck, test. Pushing to `main` deploys to GitHub Pages.
Git hooks (lefthook): pre-commit formats + lints staged files, pre-push runs tests.

Environment: macOS, zsh. A dev server stopped on purpose (killed after a check) exits with code 143 (SIGTERM):
that is a normal shutdown, not a crash; nothing to fix. Port 5173 is often taken, Vite then picks the next one (5174).

## Layout

- `index.html` — all markup (edit section with header/editor/keybar/controls, play section with stage/hud/log/boot/codeview, the program drawer, the cheat-sheet drawer, toast). The header's buttons sit in `.hbtns`: the cheat sheet, `#btn-view` (a mode's own view, hidden when it has none; second from the right, where the view's own header has its way back), mute. The status line is `.status` (a view's header uses it too).
- `src/main.ts` — app shell: layout (phone vs. split view ≥820px), run/edit, hot-swap, drawer, cheat sheet, mode switching. Holds `mode` (the `ModeDef`) and `code` (its loaded `ModeCode`); `switchMode()` is async (awaits `load()`, newest tap wins via a ticket, a failed load toasts and stays). The first mode is awaited with top-level await before the UI wires up. Links: `?mode=<id>&code=<text>` picks the first mode, and with `code` opens stage-only view at the end of the file, waiting for RUN (sound and fullscreen need that tap; it does not autoplay); the parameters are then removed from the URL. `window.KEYMASH` is the debug/browser-test handle.

- `src/modes/mycelium/` — `ground.ts` (pure: `readGround(src)` → the curve's swells and mounds, soil horizon depths, noise drift, the moss hill behind (`ridgeAt`: big elliptic moss cushions every `RIDGE_SPACING`, each top `RIDGE_RISE` over the floor, one smaller, lower cushion in every gap, joined by a smooth maximum over a base sunk under the floor), what lies buried, the trees and their canopy; further back smaller by `DEPTH_SHRINK`); `TREE_SCALE`), `crown.ts` (pure: `readCrown(r, trees, x0, x1)` → per tree the six canopy pieces of `PLAN`, and in about half the crowns a lobe hanging low toward a neighbour (`LOBE_*`), over its trunk top in `TREE_SCALE` units (not the tree's own scale), in drawing order: tree by tree from the back, each crown's pieces `behind` its trunk first (layers 0–1, the lobe, and in `BEHIND_CHANCE` of crowns one of the lower pieces), then the rest, each group back to front by `layer` (`LAYERS`; at most `CROWN_PIECES`), each a U: a lopsided, wobbling superellipse underside with sides running up out of the world, back pieces wide enough to close the canopy (the end trees' reaching out of the world), the lower ones hiding the trunk's cut top; `fetchTrunks(ids)`: only the trunks a forest stands, each fetched once (`TREE_PAGES`, their reliefs); `CANOPY` / `LEAF_FILL` per kind of leaves, `s` per texel), `assets/` (the forest library copied from `scripts/forest/samples/pack`, as pack.py wrote it; ignored by oxfmt; new textures come from `scripts/forest/12-library.ts` + `matte/pack.py`; trees one per page, each with a `relief-trees-<n>` page beside it: normal + depth from Depth Anything V2 run locally by `matte/relief.py`), `gl.ts` (WebGL2 helpers; the scene target carries a depth buffer), `render.ts` (`ForestRenderer`: 2D camera `cam` + `zoom`, `pan`, `zoomAt`; painter's order is also depth: one slot per layer, trunk and canopy piece (`SLOT`, `forestOrder()` → `order`, `at(slot)` sets it through `depthRange`; every vertex shader puts z at 0; a new layer takes a slot). The canopy is opaque: each piece's mesh is cut where `crown.frag` would turn translucent (`CROWN_OPAQUE`) into its body (fan + inner band of the ribbon, `crownBody` indices first) and its fringe of hanging leaves (`crownFringe`: `crown.frag` built with `CUTOUT`, alpha-tested at half coverage instead of blended); `drawCanopy` draws every body, then every fringe, front to back, unblended, writing depth, so each pixel is shaded once by the nearest leaves; then, tested against that depth without writing it, layers sky → ridge (moss hill: band + moss body) → ground → trunks (`drawTrunks`, tree by tree in `order`, blended at their slots between their crowns' pieces: `addTrunks()` before `setGround()`; its picture and grade, the ground projected onto its foot, handed over in height blends by its relief) → buried (treasure halos, shadows, pictures, gem glints; a draw per atlas and pass) → post into a budget-sized target. Crowns: the canopy strip along each U in the strip's Voronoi cells, hanging along the outline's normal, the leaf fill hex-tiled as the body, `LEAF_SCALE`, recoloured by the tree's season in its kind's colours and its tint; lit clumps; a tree further back fades into the air by `HAZE`. The canopy's faked shade (column shade between a crown's own pieces only, occlusion behind pieces drawn later, every piece's column shade on trunks, hill and floor) is baked by `bakeShade()` in `build()` into the shade map (`SHADE_*`: an RG8 array over the whole world, 16 units a texel, red shade, green occlusion; layer 0 the floor's, `SHADE_TRUNK + tree`, `SHADE_PIECE + piece`; bound to `SHADE_UNIT` for the frame); receivers read it with one lookup. `wire` draws every draw's edges coloured per shader/material, `wireLegend()` — a new layer adds its colour there), `shaders/` (one GLSL piece per file, imported `?raw`, assembled in `shaders/index.ts`: `noise`, `camera`, `blend` (height blend), `hex` (hex tiling), `air` (the air's colour at a height: sky and haze), `soil` (horizons), `mossfill` (hex-tiled moss carpets), `strip` (a ground strip in 1D Voronoi cells, no mirror axes; `uCellSeed` per layer), `groundat` (the floor and its strip texel at any world point, from the ground mesh's columns as a float texture), `crown` (the pieces' shapes from `uPieces` / `uPieceShape` / `uPieceCount`, their column shade and occlusion, skipping pieces that can't reach a pixel: used by `shade.frag` to bake and by `crown.frag` for `pieceSd`; `CROWN_PIECES` is written in by `index.ts`, and `CROWN_OPAQUE` into `crown.frag`), `shademap` (`shadeAt(p, layer)`), `leaves` (leaf fill, per-kind season palettes), then each stage's `main()`; `wire.*` for the debug wireframe), `player.ts` (drag/scroll pans, pinch/ctrl+scroll zooms; fetches a forest's trunks before showing it, an edit's once they arrive, the newest edit winning; in dev builds a grid corner button toggles the wireframe). No language and no cheat-sheet cards yet. A new text needn't transition smoothly: the forest will later drop away and be recreated per text, so don't spend effort on smooth changes between texts.

Each SVG is imported with `?url` and drawn as a CSS `mask-image` over `currentColor` (`icon.css.ts`), so it is 1em and takes the text colour. `km-button icon=`, `KmItem` `icon`, `KmSelect` `icon`, `toast(text, icon)`, the key bar's cursor keys use it. `iconCursor(name, color)` makes a CSS cursor of an icon (outlined, hotspot in the middle). `src/ui/storage.ts` — the shell's draft and save slots; `readJson` / `writeJson` for a mode's own data. `km-button variant="tool"` with an `active` attribute: a lab tool.
- `src/ui/components/` — light-DOM custom elements (`km-button`, `km-mute`, `km-mode-icon`, `km-item`, `km-select`, `km-toast`, `km-drawer`, `km-card`), each registered with `customElements.define` + `HTMLElementTagNameMap`, re-exported from `index.ts`. The cheat sheet is a second `<km-drawer id="sheet">` filled with `KmCard.intro()` + `KmCard.grid(cards, onPick)`; a card is a button, `main.ts` `addLine()` appends its snippet as a new last line (no focus, so no phone keyboard) and the sheet stays open.
- Fullscreen: `<km-button id="btn-full" variant="corner">` in `#stageWrap`; `stageOnly()` in `main.ts` toggles `#app.stageonly` (CSS in `global.css.ts` hides `#edit`, `#codeview`, `.playbtns`; the players refit via their ResizeObserver) and requests real fullscreen on `<html>` when `document.fullscreenEnabled`; `fullscreenchange` to none (Esc) clears the class.
- `src/styles/theme.css.ts` — theme contract (`vars`, `layout`, `rgba()`); `global.css.ts` — shell styles (header grid areas: icon, logo, ver, status, sheet, mute). Each mode's `theme.css.ts` fills the contract via `createTheme`.
- `scripts/sheet.ts` — starts a Vite dev server (config-less: vanilla-extract + version defines), opens `scripts/sheet/index.html` in Chromium, calls `window.shots()` (`scripts/sheet/shoot.ts`: replays each card through the real VM/`Renderer` or `Petri`/`MicroRenderer` in simulated time, `Math.random` seeded per card), writes the WebPs and rewrites the README table between `<!-- sheet:start … -->` / `<!-- sheet:end -->`. A new mode needs its own capture function in `SHOOT`.
- `scripts/icons.ts` — renders `scripts/icon.svg` to the PNGs in `public/` (byte output differs between Chromium versions; don't commit re-renders of an unchanged icon). `scripts/ui-icons.ts` — the UI icon list + downloader (see `src/ui/icon.ts`). `scripts/checker-lint.ts` — oxlint + oxfmt report for the dev overlay.
- `scripts/perf.ts` — MYCELIUM_ perf harness: headless Chromium on the real GPU (ANGLE Metal), a Vite server with COOP/COEP (5 µs timers), opens `scripts/perf/index.html`, calls `window.bench()` (`scripts/perf/bench.ts`: the real `ForestRenderer`, budget pinned to one rung, camera `VIEWS` home/wide/close/canopy/crowns/soil), writes `scripts/perf/out/<label>/` (gitignored: report.md, result.json, scene + overdraw pictures, `--trace` a Chrome trace). `scripts/perf/gltrace.ts` (`traced()`, `GLTrace`) patches the WebGL2 context the renderer gets: draws grouped by the fragment shader's export name in `shaders/index.ts` (buried by `PASS`), `skip`/`only` per group or `group#n`, uniform `overrides` (the `--set` variants), timer queries, and `counting` (each program's vertex shader with a counting fragment shader, additive: overdraw). On Apple GPUs timer queries split the render pass (their sum is many times the frame): trust ablate (`skip`) there. A new layer needs no harness change unless it adds a program that should split into several groups (then extend `group` in bench.ts). Workflow: `--label before`, change, `--compare before`; `--per-draw` for which draw costs, `--heatmaps` per group.

## Conventions

- Styles: vanilla-extract only (`*.css.ts`), components keep their styles next to them. Colours via theme tokens (`vars.*`, `rgba(vars.rgb.fg, a)`), never hardcoded per mode in shared UI.
- Text: every string goes through `defineMessages(en, de)` — shared UI in `src/i18n.ts`, mode text in `src/modes/<id>/messages.ts`. `de` must mirror `en` exactly (tsc enforces). Markup uses `data-i18n`, `data-i18n-title`, `-aria-label`, `-placeholder`. `km-button` `label`/`title-key` are shared message ids. German is casual "du", short.
- Icons: buttons, drawer rows, selects and toasts show icons from `src/ui/icon.ts` (one set: MingCute, filled), never emoji or symbol characters (▶, ✖, ⛶). A new icon: add it to `ICONS` in `scripts/ui-icons.ts`, run `bun scripts/ui-icons.ts`, commit the SVG and `src/ui/icons/index.ts`. Emoji stay where they are program text: demos, the key bar's emoji keys, what a running program shows.
- Shared code (`src/lang/`, `src/engine/`, `src/ui/`, `src/main.ts`, `src/i18n.ts`) never imports from `src/modes/<id>/` (only the registry `src/modes/index.ts`); a mode's interpreter, events and effects live in its folder. Several more modes are planned — keep it that way.
- A mode's `index.ts` is in the main bundle: only light imports there (messages, theme). Anything heavy belongs behind `mode.ts`. Check the build output: each mode should be one `mode-*.js` chunk.
- Adding a KEYMASH_ effect = new `VMEvent` variant in `src/modes/keymash/types.ts`; the compiler points at every handler. A new sound kind goes into `src/engine/sound.ts`.
- The interpreter must stay total: any input (emoji, lone surrogates, NUL) must not throw — the fuzz test guards this.
- The stage canvas is shared by the 2D players; only the `active` one sizes it. A mode that needs WebGL brings its own canvas (see COOKIE_).
- Changing a card's snippet, name or timing in `sheet.ts`: re-run `bun scripts/sheet.ts` and look at the pictures (they must show something recognisable at ~170 px wide).
- Respect `prefers-reduced-motion` (`gentle` flag in both renderers).
- Comments explain *why*, in plain short sentences; keep the existing tone.
- Keep README in sync when behaviour, scripts or the language change.

## Commits

- Small and focused: one feature, fix or chore per commit, with its docs. Commit each step as soon as it works (checks green) instead of piling everything into one commit at the end.
- Message style: `Topic: what changed and why`, one line, e.g. `Mode transitions: clear every mode's animation class first, so KEYMASH_'s glitch plays after PETRI_ too`.
